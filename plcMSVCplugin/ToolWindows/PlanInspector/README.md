# Инспектор плана Planning C (Plan Inspector)

В этой папке находятся компоненты визуального инструментального окна (Tool Window) **«Инспектор плана и состояния потоков Planning C»**.

> Полное руководство и спецификация инспектора плана: [PlanInspector.md](PlanInspector.md).

Окно предназначено для визуализации кольцевых буферов задач `circular_list`, отслеживания параметров вызовов планируемых процедур, анализа каналов данных `funnel`/`cfunnel`, инспекции топологий и мониторинга потоков операционной системы в моменты останова отладчика.

---

## Архитектура инструментального окна Visual Studio

1. **`PlanInspectorToolWindow.cs`:**  
   Класс-обертка, наследующий `ToolWindowPane` из Visual Studio Shell.
   * Регистрирует уникальный GUID окна: `7b594b28-765f-464a-a309-87a2245c4786`.
   * Задает системный заголовок: `Инспектор плана и потоков Planning C`.
   * Внедряет WPF-компонент `PlanInspectorControl` в качестве содержимого окна через свойство `Content`.

2. **`PlanInspectorControl.xaml`:**  
   Пользовательский интерфейс WPF, стилизованный под светлую и темную темы Visual Studio через динамические ресурсы `EnvironmentColors`.

3. **`PlanInspectorControl.xaml.cs`:**  
   Логика инспекции и двустороннего взаимодействия с нативным отладчиком Visual Studio через COM-модель автоматизации `EnvDTE.DTE2`.

## Панель быстрого управления (Command Bar)

В верхней части окна расположена фиксированная панель быстрых действий:
* **Кнопка «Отладка Planning C» (`Shift+Alt+F5`):**  
  Сохраняет документ, запускает `PlanningCDebuggerLauncher.LaunchDebugAsync()`, транслирует, компилирует и подключает отладчик.
* **Кнопка «Без отладки» (`Ctrl+F5`):**  
  Запускает `LaunchRunAsync()` в отдельном консольном окне Windows с паузой по завершении.
* **Кнопка «Очистить .plc_build»:**  
  Удаляет артефакты сборки активного файла.
* **Кнопка «Обновить»:**  
  Вручную перезапрашивает память отладчика и перерисовывает все вкладки инспектора.
* **Чекбокс «Автообновление при останове» (`ChkAutoRefresh`):**  
  Если включен, при каждом срабатывании точки останова или пошаговой трассировке (`F10`/`F11`) данные обновляются автоматически.
* **Индикатор статуса (StatusIndicator):**  
  * Серый: программа не запущена / отладчик остановлен;
  * Оранжевый: идет трансляция или компиляция;
  * Зеленый: программа выполняется на процессоре (Run Mode);
  * Красный: программа остановлена на точке останова (Break Mode).

## Описание вкладок инспектора

Окно разделено на 5 специализированных вкладок:

### Вкладка 1. Потоки и стек вызовов (Threads)
Предназначена для контроля параллельных потоков конвейера или OpenMP.
* **Таблица `GridThreads` (модель `ThreadItemModel`):**
  * `ID`: системный идентификатор потока ОС.
  * `Имя`: имя потока (главный поток Master/Worker или фоновый поток рантайма).
  * `Состояние`: `[Текущий] Точка останова`, `Приостановлен` или `Активен`.
  * `Выполняемая функция / модуль`: текущая функция на вершине стека и имя модуля (`.exe`/`.dll`).
  * `Приоритет`: системный приоритет потока.
* **Список `ListCallStack`:**  
  При выборе любого потока в таблице ниже отображается полный стек вызовов выбранного потока.
* **Переключение потока:**  
  Двойной щелчок по строке потока делает его активным в контексте отладчика Visual Studio.

---

### Вкладка 2. Состояние плана (Plan State)
Центральная вкладка плагина, предназначенная для инспекции очередей `plan_first`/`plan_last`.
* **Статусные плашки:**
  * Имя активной процедуры Planning C (например, `PutTree`).
  * Текущая стадия конвейера (`reent_stage()`) и общее число стадий (`reent_num_stages()`).
  * Количество задач в очереди кольцевого буфера `circular_list`.
  * Режим параллелизма: последовательный или параллельный конвейер.
* **Таблица `GridPlanTasks` (модель `PlanTaskItemModel`):**
  * `№`: порядковый номер задачи в очереди (1, 2, ...).
  * `Процедура`: имя целевой функции рантайма (`PutTree`, `_call_PutTree`).
  * `Параметры`: строковое представление формальных параметров (`Cur=0x..., Ins=0x...`).
  * `Значения полей (Data)`: результат безопасного разыменования указателей (`*Cur->Data=20`).
  * `Статус / Флаги`: маркер задачи (обычная задача, барьер или маркер параллелизма).
* **Поле детализации (`TxtTaskDetail`):**  
  Подробный текстовый дамп выделенной задачи с разворотом всех членов структуры и адресов памяти.
* **Иерархическое дерево (`TreePlan`):**  
  Древовидное представление стадии конвейера, процессора и всех слотов кольцевого буфера.

---

### Вкладка 3. Отображение содержимого (Channels & Data)
Служит для мониторинга межпоточных каналов связи Planning C (`funnel`, `cfunnel`, `cvar`).
* **Таблица `GridFunnels` (модель `FunnelItemModel`):**
  * `Имя канала`: идентификатор переменной (например, `V`, `in_channel`).
  * `Направление`: входной (`funneled_in`), выходной (`funneled_out`) или кольцевой (`cfunnel`).
  * `Емкость буфера (N)`: вычисляется через вызов метода `getN()`.
  * `Состояние`: `Пуст (Ready)` или `Содержит данные` (на основе `empty()`).
  * `Предпросмотр содержимого`: значения первых элементов массива `Data[0..3]`.
* **Поле детального просмотра (`TxtBufferDetail`):**  
  Отображает полный дамп ячеек канала `Data[0] .. Data[capN-1]`, тип элементов и Natvis-строку.
* **Реестр `__Funnels`:**  
  Отображает статус глобального диспетчера каналов данных в системе.

---

### Вкладка 4. Топология (Topology)
Отображает структуру многопроцессорной или распределенной виртуальной топологии:
* **Идентификатор процессора (`plan_processor_id`):** номер текущего логического узла.
* **Всего процессоров (`plan_processors`):** общее число узлов в топологии.
* **Линейный номер узла (`plan_linear_num`):** одномерный индекс в глобальной сетке.
* **Номер в топологии (`plan_topology_num`):** координаты в многомерной топологии (тор, гиперкуб, решетка).
* **Статус параллельного флага (`*__parallel_flag__`):** признак активации параллельного конвейера OpenMP/MPI.

---

### Вкладка 5. Журнал сборки (Log)
Встроенная консоль протоколирования операций:
* Логирование по шагам с таймштампами `[ЧЧ:ММ:СС]`.
* Вывод командных строк запуска `Reenterable.exe` и `cl.exe`.
* Полные диагностические сообщения об ошибках компилятора MSVC и транслятора.
* Автоматическая прокрутка к последней строке (`ScrollToEnd`).

## Внутренние алгоритмы инспекции на точке останова

### 1. Перехват событий отладчика
В конструкторе или при активации окно подписывается на события:
```csharp
dte.Events.DebuggerEvents.OnEnterBreakMode += DebuggerEvents_OnEnterBreakMode;
dte.Events.DebuggerEvents.OnEnterRunMode   += DebuggerEvents_OnEnterRunMode;
```
* При переходе в `BreakMode` контрол автоматически запускает чтение памяти и, если очередь задач не пуста, переключает фокус на вкладку «Состояние плана».

### 2. Поиск очереди задач в стеке (`queueExpr`)
Контрол инспектирует локальные переменные текущего кадра стека (`CurrentStackFrame.Locals`):
* Ищет переменную `__event_list__` или структуры, имена которых начинаются с `_events_` (например, `_events_PutTree` или `_events_PutTree__LOC__`).
* Если локальных переменных нет в области видимости, перебираются кандидаты глобального контекста.

### 3. Чтение характеристик кольцевого буфера (`Begin`, `End`, `N`)
Через метод `SafeGetExpression` плагин запрашивает у отладчика поля внутренней структуры `circular_list`:
```csharp
DteExpression expBegin = SafeGetExpression(dte, $"{queueExpr}->Begin");
DteExpression expEnd   = SafeGetExpression(dte, $"{queueExpr}->End");
DteExpression expN     = SafeGetExpression(dte, $"{queueExpr}->N");
```
* Размер очереди вычисляется по циклической формуле:  
  `tasksCount = (queueEnd - queueBegin + queueCap) % queueCap;`
* Поддерживается гибкий парсер `TryParseIntFlexible`, корректно обрабатывающий как десятичные, так и шестнадцатеричные значения отладчика (`0x00000001`).

### 4. Извлечение элементов плана и разыменование указателей
Для каждого индекса задачи в кольцевом буфере `Data[slot]`:
* Считываются поля параметров структуры задачи (`Cur`, `Ins` и т.д.).
* Если параметр является указателем (`TreeNode *`), плагин безопасно разыменовывает его и читает внутренние данные: `(*Cur)->Data`.
* Выполняется строгая проверка на нулевые указатели (`IsNullOrZero` для `NULL`, `nullptr`, `0x0`), что исключает сбои `COMException` при чтении листьев дерева.
* Заполняется коллекция `PlanTasks`, привязанная к таблице `DataGrid`.
