# Руководство разработчика: Добавление ключевых слов и доработка синтаксиса

Данное руководство кратко освещает вопрос о том, как вносить изменения в плагин Planning C при введении нового ключевого слова, типа данных, директивы препроцессора или оператора в язык, и как настроить для него подсветку.

---

## Архитектура подсветки синтаксиса

Язык Planning C строится поверх стандартного C/C++ (ISO C99/C11 / C++). Вся разработка и примеры ведутся непосредственно в стандартных файлах **`.cpp`** (и `.h`).

В плагине используется **нативный MEF-классификатор ([`PlanningCClassifier.cs`](plcMSVCplugin/Editor/PlanningCClassifier.cs))**:
- Он напрямую подключается к встроенному редактору C/C++ Visual Studio (`Source Code Editor`);
- Все ключевые слова, типы данных и правила вынесены в конфигурационный файл — [`plcMSVCplugin/syntax_rules.json`](plcMSVCplugin/syntax_rules.json);
- Чтобы добавить или изменить слова, **не нужно модифицировать исходный C#-код и регулярные выражения**.

---

## Как добавить новое ключевое слово в язык

Все токены распределены по массивам в файле `plcMSVCplugin\syntax_rules.json`.

### Шаг 1. Откройте `syntax_rules.json`

Найдите нужный массив и добавьте строковый элемент:

1. **Ключевое слово управления, планирования или параллелизма (синяя подсветка)**:
   Добавьте слово в массив `"keywords"`:
   ```json
   "keywords": [
     "reenterable",
     "chain",
     "plan_first",
     "plan_last",
     "новое_слово"
   ]
   ```

2. **Новый тип данных, виртуальная топология или канал (бирюзовая/зеленая подсветка)**:
   Добавьте тип в массив `"types"`:
   ```json
   "types": [
     "funnel",
     "cvar",
     "topology",
     "новый_тип"
   ]
   ```

3. **Новая директива препроцессора `#...`**:
   Добавьте имя директивы (без знака `#`) в массив `"preprocessor"`:
   ```json
   "preprocessor": [
     "def_pattern",
     "def_module",
     "моя_директива"
   ]
   ```

4. **Ключевые слова встроенного Prolog**:
   Добавьте слово в массив `"prologKeywords"`:
   ```json
   "prologKeywords": [
     "is",
     "fail",
     "xpathf",
     "новое_правило"
   ]
   ```

5. **Слова для русского естественно-языкового программирования `#( ... )`**:
   - Существительные и их формы: добавьте в массив `"russianTypes"` (`"вектор"`, `"скаляр"`, ...).
   - Действия и глаголы: добавьте в массив `"russianKeywords"` (`"Составить"`, `"Ввести"`, `"Найдем"`, ...).

---

## Настройка цвета токена (при необходимости)

Если токен добавлен в одну из существующих секций (`keywords`, `types`, `preprocessor`, `russianTypes`, `russianKeywords`), цвет применится автоматически:
- `keywords` $\rightarrow$ Синий (ключевые слова)
- `types`, `russianTypes` $\rightarrow$ Бирюзовый / Зеленый (типы данных и топологии)
- `preprocessor` $\rightarrow$ Фиолетовый / Синий (директивы `#...`)
- `russianKeywords` $\rightarrow$ Синий (действия)

Если требуется создать принципиально новую категорию токенов, привязка к системным цветам Visual Studio задается в конструкторе `PlanningCClassifier` в [`PlanningCClassifier.cs`](plcMSVCplugin/Editor/PlanningCClassifier.cs).

## Рекомендации по написанию кода на Planning C

При написании программ и создании новых конструкций синтаксиса следует учитывать особенности внутреннего препроцессора `Reenterable.exe`:

1. **Именование переменных и аргументов:**
   - Избегайте использования служебных имен и макросов Free Pascal в качестве идентификаторов параметров (например, `DATA`, `SELF`, `RESULT`). Рекомендуется использовать описательные имена (`data`, `item`, `val`, `buffer`).
2. **Сигнатуры функций стадий конвейера (`chain` и `throw`):**
   - Если функция стадии конвейера содержит спецификатор передачи `throw(тип имя, ...)`, ее сигнатура должна явно содержать соответствующие формальные параметры.
   - Корректный паттерн конвейера с передачей через каналы:
     ```cpp
     chain Producer(funnel(out, int) * V) {
         int item = 42;
         V->put(&item);
     }

     chain Consumer(funnel(in, int) * V) {
         int item;
         V->get(&item);
     }
     ```
3. **Нумерация стадий:**
   - Если программа использует реентрабельные функции со стадиями (`Stage0`, `Stage1`, ...), нумерация должна начинаться с 0, либо определяться явными функциями переходов.

## Шаг 2. Сборка и проверка

После редактирования `syntax_rules.json` запустите сборку расширения:
```powershell
.\build_vsix.ps1
```
или выполните:
```powershell
dotnet build plcMSVCplugin/plcMSVCplugin.csproj -c Release
```

Скрипт пересоберет расширение и обновит файл `PlanningC.vsix` в корне репозитория.
Установите его и проверьте подсветку нового синтаксиса в тестовом файле `plcMSVCplugin\test_samples\test_syntax.cpp` или `plcMSVCplugin\test_samples\reent.cpp`.
